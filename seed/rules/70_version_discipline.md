# 70 · 版本纪律（一次任务只留最终版）

> 改多版后电脑里堆一堆半成品，是这类工作流最常见的浪费。
> 这条规则把这个动作固化下来。

## 一、规则

| 阶段 | 做法 |
|---|---|
| 写第一版 | `promptlib_draft`，任务名全程不变 → `workspace/<任务名>/v1.md` |
| 每次改版 | 同一任务名再调 `promptlib_draft` → 自动 `v2.md`、`v3.md`… |
| 定稿 | 只把最终版写进 `output/<任务名>.md` |
| 收尾 | 用户说「完成」→ 我预演 → 用户确认 → `promptlib_finalize` 真删中间版 |

**中间版本一律不出现在 `output/`、`rules/`、`samples/`、`material/`。**

## 二、什么叫「任务完成」

用户在对话里说下面任一类话即算收尾信号：

- **完成** / **完成任务**
- 就这样 / 定了 / 可以了 / 这版可以
- 收尾 / 结束这个

## 三、收到收尾信号后的四步

1. **确认最终版是哪一版**，把这版完整重列一遍（不让用户翻上文）。
2. 调 `promptlib_finalize`（**不传 confirm**）→ 只预演，列出「保留 v3、将删 v1、v2」。
3. **问一句**：「确认删除中间版、只留 v3 吗？」
4. 用户说「确认 / 删 / 可以」之后，才传 `confirm=true` 真删，并回报：保留哪版、删了几个、归档到哪。

## 四、不许做的事

- ❌ 没经用户同意就删文件
- ❌ 删除范围越过该任务自己的工作区（`rules/`、`samples/`、`output/` 永不碰）
- ❌ 把中间版留在 `output/` 或散落到库外
- ❌ 用户说「完成」，却不问一句就当作清理已完成

## 五、工具边界（技术事实）

- 删除只在 `workspace/<任务名>/` 内进行，且只删形如 `vN.md` 的文件
- `keep` 省略时自动保留编号最大的一版
- `promote` 默认 true：把最终版复制到 `output/<任务名>.md`，原 `vN.md` 保留
- 目录里非 `vN.md` 的文件（比如用户自己放的参考说明）**不会被删**
